## 二、背景与目标

### 2.1 背景

考研择校（锁定唯一报考志愿）是备考期最关键、也最焦虑的决策。基于本项目前期调研（《五方向创意清单》2026-10-12）：

- 报名规模趋于高位：全国考研报名人数 474 万(2023) → 438 万(2024) → 388 万(2025) → 343 万(2026)，而招生规模约 130 万，**总量回落不等于难度下降**，热门专业复试线不降反升（来源：本项目调研报告，原始出处为教育部/研招网公开数据）。
- 核心痛点：① **真实统考名额不透明**（招生简章常混算推免，部分院校推免占比极高）；② **上岸概率无法量化**，考生只能凭经验"拍脑袋"。
- 决策高峰：**9-10 月报名期**（必须锁校）为第一刚需窗口。

### 2.2 要解决的问题

| 编号 | 问题 | 现状 |
|------|------|------|
| P-1 | 院校专业数据分散、口径不一、更新滞后 | 考生在多个网站/群聊之间手工拼凑 |
| P-2 | 缺少"我的分数 → 我能上哪些院校"的量化匹配 | 依赖经验或付费咨询，黑箱且昂贵 |
| P-3 | 偏好（地域/研究方向/学费/学硕专硕）难以纳入决策 | 大量人工比对，易遗漏 |

### 2.3 产品目标

用「结构化院校数据库兜底事实 + 大模型做理解与排序」的方式，让考生在 3 分钟内得到一份**可解释、可溯源、可调整**的择校志愿方案。

### 2.4 成功指标与口径

| 指标 | 口径定义 | 目标值 | 说明 |
|------|----------|--------|------|
| 方案生成成功率 | 生成成功请求数 ÷ 生成请求总数（含重试后成功） | ≥ 99% | 排除用户主动取消 |
| 方案生成时延 P95 | 从点击「生成方案」到结果渲染完成 | ≤ 30s | AI 推理 + 渲染 |
| 方案保存/导出率 | 生成后可导出数 ÷ 生成总数 | ≥ 40% | **估算值**，需上线后校准 |
| 事实一致率 | 方案中分数线等数字与数据库一致条数 ÷ 全部数字条数 | 100% | 硬性红线：不允许出现库外数字 |
| 次日留存 D1 | 生成方案用户次日回访 ÷ 当日生成用户 | ≥ 25% | **估算值** |

> 说明：≥ 40% 与 ≥ 25% 为初始目标估算，非实测；上线 2 周后以真实数据校准。

## 三、名词与术语定义

| 术语 | 定义与口径 |
|------|-----------|
| 国家线 | 教育部统一划定的初试成绩基本要求，分 A 区 / B 区 |
| A 区 / B 区 | A 区含北京、上海等 21 省市；B 区含内蒙古、广西等 10 省区。B 区国家线通常低于 A 区 |
| 报考省份 | 考生选择的报考点所在省份，用于判定 A/B 区与地域偏好 |
| 初试科目组合 | 政治(100) + 外国语(100) + 业务课一(150) + 业务课二(150)，总分 500；管理类联考为 199 管综 + 204 英语二，总分 300 |
| 报录比 | 报考人数 ÷ 录取人数（值越大竞争越激烈） |
| 复录比 | 进入复试人数 ÷ 实际录取人数（如 1.2:1 表示 1.2 个复试者录 1 个；值越接近 1 竞争越缓） |
| 统考名额 | 招生计划总数扣除推免录取数后的真实统考录取名额（**本产品强调透明展示**） |
| 专硕 / 学硕 | 专业学位 / 学术学位，学制、学费、培养目标与报考代码不同 |
| 冲 / 稳 / 保 | 择校方案中的三档推荐：冲=略高于自身分数区间、稳=匹配区间、保=低于区间 |
| 上岸概率 | 系统基于历史数据的**估算**区间（区间形式呈现，如 45%-60%），非承诺 |
| 择校方案 | 本产品核心产出物：单志愿规则下，冲/稳/保三档候选院校专业清单 + 依据 |

## 四、需求范围

### 4.1 本期包含（V1.0）

- 考生信息采集（省份、初试科目组合、成绩、本科背景）
- 兴趣偏好采集（目标院校、地域、研究方向、优先策略、学业规划、学费倾向、学硕/专硕倾向）
- 院校专业数据库检索（分数线、报录比、复录比、统考名额、学费）
- 大模型生成择校志愿方案（冲/稳/保三档 + 上岸概率 + 依据溯源）
- 方案查看、调整、保存、导出
- 免责声明与合规提示

### 4.2 本期不包含（明确不做）

| 不做项 | 原因 |
|--------|------|
| 高考式平行志愿"梯度填报" | 考研初试为「一校一专业」单选，梯度填报场景在此阶段不成立（详见第五章） |
| 调剂季多平行志愿模拟 | 属次年 3-4 月独立场景，列入 V2.0 |
| 任何付费/增值服务 | 本期完全免费，无资金链路；变现列入后续版本 |
| 1v1 人工咨询履约 | 非本期能力域 |
| UGC 社区/经验帖 | 列入长期版本 |
| "保证上岸"类承诺 | 合规红线，永不提供 |

## 五、方案对比与选型说明

### 5.1 关键定位决策：考研没有高考式"梯度填报"

| 对比项 | 高考志愿 | 考研初试志愿（本期场景） |
|--------|----------|--------------------------|
| 志愿结构 | 多平行志愿，冲稳保梯度 | **单一院校单一专业**，一个志愿定生死 |
| 决策时点 | 出分后集中填报 | **9-10 月报名期**（先于考试） |
| 决策依据 | 往年投档线 + 位次 | 报录比 + 复录比 + 统考名额 + 自身估分 |
| 调剂机制 | 无 | 次年 3-4 月多平行调剂志愿（**梯度填报真实场景**） |

**结论**：本期所谓"填报方案"，实为**择校决策方案**——在单志愿约束下，给出冲/稳/保三档候选院校专业，辅助用户**锁定那唯一一个报考志愿**。"梯度/平行志愿模拟"能力后置到 V2.0 调剂季场景（见 13.1 演进路径）。

### 5.2 技术路线选型：大模型 vs 纯规则引擎 vs 混合

| 方案 | 实现成本 | 复杂度 | 体验 | 风险 | 结论 |
|------|----------|--------|------|------|------|
| 纯大模型生成（模型内置知识） | 低 | 低 | 流畅但事实不可控 | **高**（数据过时/幻觉） | 否决 |
| 纯规则引擎匹配 | 中 | 中 | 稳定但机械，难理解自然语言偏好 | 中 | 备选 |
| **结构化数据库 + 大模型混合**（推荐） | 中高 | 中高 | 事实准 + 表达自然 + 可解释 | 可控 | **推荐** |

**推荐理由**：由**自建院校数据库提供全部事实**（分数线/报录比/复录比/名额），大模型**只负责理解用户自然语言偏好、做加权排序与文案生成**，所有数字必须来自数据库并可溯源。不选纯大模型的原因是事实不可控——填报决策容错率极低，错一个分数线即毁口碑。

### 5.3 演进路径

| 版本 | 时间窗 | 能力 | 触发条件 |
|------|--------|------|----------|
| V1.0（本期） | 2026 年 10 月 | 择校方案生成（单志愿） | 立项即启动 |
| V1.1 | 2026 年 11-12 月 | 方案对比、收藏、数据变动提醒 | V1.0 数据底座稳定 |
| V2.0 | 2027 年 3-4 月 | 调剂季多平行志愿梯度模拟 | 调剂规则与缺额数据接入就绪 |

## 六、用户角色与使用场景

### 6.1 用户角色

| 角色 | 画像 | 核心目标 | 使用频率 | 信息水平 |
|------|------|----------|----------|----------|
| 应届考生 | 大四在读，首次考研，对规则不熟 | 快速缩小择校范围 | 报名期高频 | 新手 |
| 往届考生（二战/三战） | 已毕业，经验丰富、极度看重确定性 | 验证自己的判断、找确定性 | 报名期高频 | 熟练 |
| 跨考考生 | 本科与目标专业不一致，信息差最大 | 找到友好度高的院校 | 中频 | 新手 |
| 在职考生 | 边工作边备考，时间紧 | 快速拿到结论 | 低频 | 熟练 |

> 画像基于项目调研结论构建；具体人群规模比例待后续问卷校准，标注为**待确认假设**。

### 6.2 核心使用场景（主流程）

```
新用户进入 → 填写考生成绩与背景 → 填写兴趣偏好 → 点击「生成方案」
  → AI 生成择校方案（冲/稳/保三档）→ 查看/调整 → 保存/导出
```

### 6.3 分支与异常场景

| 场景 | 预期表现 |
|------|----------|
| 成绩未填/科目未选 | 阻断生成，高亮缺失项并追问 |
| 偏好全部留空 | 允许生成，使用默认策略并明确提示"未使用偏好加权" |
| 分数极低（低于所有库内院校） | 输出保底建议 + 调剂指引，不强行推荐 |
| 目标院校不在库内 | 明示"暂无数据"，提供相近院校替代，不编造 |
| 数据库/模型不可用 | 明确报错 + 重试入口，不返回空白方案 |

## 七、功能需求

> 每条需求均有唯一编号，验收标准采用 Given/When/Then。

### FR-01 考生信息采集

**描述**：采集生成方案所需的考生基本信息与成绩。
**必填字段**：报考省份、初试科目组合、各科成绩（政治/外国语/业务课一/业务课二/总分）、本科院校层次、本科专业、是否跨考。
**选填字段**：关注的目标专业（用于关联展示报考人数信息）。
**业务规则**：
- 总分 = 各科之和，系统自动校验，不一致时提示。
- 报考省份自动映射 A 区 / B 区，并提示对应国家线。
- 「考研报考人数信息」为系统展示项：用户选定目标专业后，系统从数据库显示其往年报考人数/报录比。

**验收标准**：
- Given 用户填写省份「江苏」并选择科目组合「政治+英语一+数学一+408」，When 保存信息，Then 系统显示"A 区"，总分自动计算并校验。
- Given 考生各科成绩之和与手动填写总分不一致，When 提交，Then 提示差额并阻断生成。

### FR-02 兴趣偏好采集

**描述**：采集用于加权推荐的偏好项。
**字段**：目标院校（可多选/关注）、地域偏好（城市/区域）、研究方向偏好、优先策略（如"求稳上岸优先"/"冲名校优先"/"地域优先"/"性价比优先"）、学业规划（就业/读博/出国）、学费倾向（敏感/一般/不敏感）、学硕专硕倾向。
**业务规则**：全部为选填；缺失项使用默认中性权重，并在方案中标注"该维度未参与加权"。

**验收标准**：
- Given 用户偏好全部留空，When 生成方案，Then 方案页明确标注"未使用偏好加权"。
- Given 用户优先策略选择"求稳上岸优先"，When 生成方案，Then 冲/稳/保三档中"稳""保"档占比提升（权重规则可配置）。

### FR-03 院校专业数据库检索

**描述**：提供院校/专业检索入口，展示分数线、报录比、复录比、统考名额、学费、参考书等。
**业务规则**：
- 所有数据标注**来源年份**与**数据版本**。
- 明确区分"招生计划总数"与"**统考名额**（扣除推免）"。

**验收标准**：
- Given 用户检索某院校某专业，When 查看详情，Then 展示近 3 年分数线、报录比、复录比、统考名额，且每条数据标注年份。
- Given 某专业当年数据缺失，When 展示，Then 明示"暂无数据"，不显示估算值。

### FR-04 大模型生成择校方案（核心）

**描述**：接收 FR-01/FR-02 输入与 FR-03 数据库事实，生成冲/稳/保三档候选择校方案。
**业务规则**：
- 大模型**不得生成任何数据库以外的分数线数字**；所有数字从数据库注入。
- 每条推荐须附：院校、院系、专业、专硕/学硕、近 3 年分数线、报录比、复录比、统考名额、估算上岸概率（区间）、推荐理由、数据来源年份。
- 上岸概率以**区间**呈现，且必须显示"估算，非承诺"。
- 详见**附录 A：AI 功能需求专项（六模块）**。

**验收标准**：
- Given 用户信息与偏好完整，When 点击生成，Then ≤30s 内返回含冲/稳/保三档、每档 ≥3 个院校专业的方案。
- Given 方案中出现任一数字，When 与数据库比对，Then 100% 一致（事实一致率红线）。
- Given 方案输出，When 检查文案，Then 无"一定录取""保证上岸""最"等违规绝对化用语。

### FR-05 方案展示与解释

**描述**：以冲/稳/保分档卡片形式展示方案，每档可展开查看依据。
**业务规则**：空/加载/错误/边界（超长文案、超多推荐）四态齐全；支持按院校/分数线排序。

**验收标准**：
- Given 方案生成中，When 用户等待，Then 展示加载进度而非空白。
- Given 推荐院校名称超长，When 展示卡片，Then 文本截断并可点击查看全称。

### FR-06 方案调整与重新生成

**描述**：用户可对推荐项标记"不考虑/优先考虑"，并基于调整重新生成。
**业务规则**：每次调整记录到反馈；重新生成保留用户已标记的偏好。

**验收标准**：
- Given 用户标记某院校"不考虑"，When 重新生成，Then 该院校不再出现在方案中（或出现但明确标注需二次确认）。

### FR-07 方案保存与导出

**描述**：保存方案到"我的方案"，支持导出为图片/PDF 便于分享。
**验收标准**：
- Given 用户点击保存，When 保存成功，Then "我的方案"列表可见该方案并含生成时间。
- Given 用户导出，When 导出完成，Then 文件含免责声明与数据来源年份。

### FR-08 免责声明与合规提示

**描述**：在采集页、生成页、导出物三处展示免责声明。
**业务规则**：文案包含"本方案由 AI 基于公开数据估算生成，仅供参考，不构成录取承诺，请务必以官方招生简章为准"。

**验收标准**：
- Given 用户首次生成方案，When 进入生成页，Then 展示免责声明且用户需勾选确认。

### FR-09 方案反馈采集

**描述**：收集字段级反馈，用于模型与规则迭代。
**业务规则**：每个推荐项支持"有用/无用/不准确"标记；可选填写理由。详见附录 A.6。

**验收标准**：
- Given 用户标记某项"不准确"，When 提交，Then 反馈入库并关联方案 ID 与数据版本。

### FR-10 用户账号与数据管理

**描述**：支持手机号/游客两种进入方式；用户可查看与删除自己的数据。
**验收标准**：
- Given 游客用户，When 使用核心功能，Then 可免登录体验（数据本地保存）。
- Given 用户点击"删除我的数据"，When 确认，Then 个人信息与方案从服务端清除。

## 九、业务流程与状态流转

### 9.1 主流程（节点 → 判断 → 分支）

```
[开始] → 采集考生信息 → 校验完整性
   ├─ 缺必填 → 高亮追问 → 返回采集
   └─ 完整 → 采集偏好 → 调用数据库检索候选池 → 调用大模型生成
        ├─ 生成失败 → 报错 + 重试入口
        └─ 生成成功 → 渲染三档方案 → 用户查看/调整
             ├─ 调整 → 重新生成（保留标记）
             └─ 满意 → 保存/导出 → [结束]
```

### 9.2 方案状态机

| 状态 | 触发事件 | 允许操作 | 迁移条件 |
|------|----------|----------|----------|
| 待生成 | 用户进入生成页 | 生成 | 必填校验通过 |
| 生成中 | 点击生成 | 取消 | 模型返回 / 超时 |
| 已生成 | 模型返回成功 | 查看、调整、保存、导出、反馈 | — |
| 生成失败 | 模型/数据库异常 | 重试、返回 | — |
| 已保存 | 点击保存 | 查看、导出、删除 | — |

**状态约束**：状态单向流转，生成中不可直接跳转已保存；失败态不缓存半成品。

## 十五、附录

### 附录 A：AI 功能需求专项（六模块）

> 生成择校方案本质是 AI 功能，传统确定性 PRD 不适用，必须补齐以下六模块。

#### A.1 任务定义

- **谁**：考研考生（应届/往届/跨考/在职）。
- **何时**：报名期锁定报考志愿时。
- **基于哪些信息**：用户填写的成绩与偏好 + 自建院校数据库历年数据。
- **要完成什么**：给出一份冲/稳/保三档、可解释、可溯源的**择校志愿建议**。
- **当前成本**：手工比对多源数据耗时数小时，或付费咨询数百至数千元。
- **AI 帮到哪一步**：**建议 + 排序 + 结构化输出**，不代替用户决策、不直接执行任何外部动作。

#### A.2 输入与上下文契约

| 项 | 约定 |
|----|------|
| 输入来源 | 用户表单（FR-01/FR-02）+ 院校数据库（FR-03） |
| 权限范围 | 仅当前用户自己的输入数据 |
| 缺失处理 | 必填缺失 → 阻断追问；偏好缺失 → 中性权重并标注 |
| 实时与历史冲突 | 一律以数据库**最新已发布版本**为准，模型禁用内部记忆数据 |
| 缺关键字段 | 缺"初试科目组合"或"报考省份"→ 停止生成并追问 |
| 超长输入 | 目标院校关注数超上限（如 20 个）→ 提示并取前 N 个 |

#### A.3 输出契约

| 项 | 约定 |
|----|------|
| 输出结构 | 方案 ID、梯度分组（冲/稳/保）、每组若干推荐项 |
| 推荐项必填字段 | 院校、院系、专业、专硕/学硕、近 3 年分数线、报录比、复录比、统考名额、上岸概率区间、推荐理由、数据来源年份 |
| 禁止内容 | 库外数字、录取承诺、绝对化用语、诱导性表述、他人隐私 |
| 证据形式 | 每个数字必须引用数据库具体年份条目（可溯源） |
| 可编辑范围 | 用户可标记"不考虑/优先考虑"并重新生成 |
| 后续去向 | 保存 / 导出（图片/PDF） |

#### A.4 质量标准与验收样本

**质量维度**：事实正确、信息完整、格式合规、表达合适、来源可靠、支持下一步决策。

| 维度 | 阈值 |
|------|------|
| 事实一致率（数字与库一致） | 100% |
| 输出格式合规率 | 100% |
| 人工评审通过率 | ≥ 90% |
| 低置信降级触发率 | 记录并监控 |

**验收样本集**：

| 样本 | 输入 | 可接受 | 不可接受 |
|------|------|--------|----------|
| 常见 | 常规分数 + 完整偏好 | 三档齐全 + 有依据 | 缺档位 |
| 缺失 | 偏好全空 | 输出 + 标注未加权 | 报错或不输出 |
| 口径冲突 | 用户关注院校与偏好矛盾 | 说明冲突 + 给权衡建议 | 静默忽略其一 |
| 超长 | 关注 30 个院校 | 截断为上限并提示 | 直接崩溃/超时 |
| 边界 | 分数低于全部库内院校 | 保底 + 调剂指引 | 硬凑推荐 |
| 拒答 | 询问"保证录取我" | 明确拒绝 + 说明不确定性 | 给出承诺 |

#### A.5 异常降级与人工接管

| 异常 | 策略 |
|------|------|
| 幻觉/库外数字 | 拦截重生成；连续失败 → 降级纯规则结果 |
| 置信度低 | 降级为"参考候选清单"，标注不确定性 |
| 该专业无数据 | 明示"暂无数据"，不猜测 |
| 多源口径冲突 | 以权威源/最新版本为准并标注 |
| 工具/数据库失败 | 报错 + 重试；持续失败给出人工咨询入口（后续版本） |
| 触发高风险规则（分数极低） | 输出保底建议 + 调剂指引 |

> 降级不是统一"系统繁忙"，而是分层给出可继续使用的产出（草稿/原始资料/进度保留）。

#### A.6 反馈与版本闭环

- **字段级反馈**：每个推荐项支持"有用/无用/不准确 + 理由"。
- **版本关联**：每条方案结果关联 模型版本 / 提示词版本 / 数据库版本 / 规则版本，可复现可追溯。
- **闭环**：反馈 → 归因 → 规则/数据/提示词迭代 → 回归验证。

#### A.7 AI 行为约束三层

| 层级 | 内容 |
|------|------|
| **Always do**（无需人工复核） | 展示数据库事实、标注数据年份、展示免责声明 |
| **Ask first**（需确认） | 必填缺失时追问；偏好极端时二次确认 |
| **Never do**（绝不越过） | 编造分数线；承诺录取；未经授权使用/外泄个人数据；越权修改数据 |
